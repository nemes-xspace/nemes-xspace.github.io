Proof of Contribution

The core technical question: did your computer actually do the work? Here's how the network knows.

Verification Design

  • 10% random recompute — every job has a 1-in-10 chance of being fully re-embedded by an independent verifier node
  • Cosine threshold — verifier vectors must match ≥ 0.99 cosine similarity against the worker's output
  • Deterministic input — job manifests are content-hashed; same input, same output, same machine-independent result
  • Reputation decay — failed verifications burn shares and reduce future job priority
  • No trust required — verifiers are economically indifferent peers, not friends of the network

Privacy Architecture

What touches the internet, what never does — stated precisely, because vague privacy claims are worthless.

What NEVER happens

  • Your personal files — never scanned, processed, uploaded or stored. The network has no access to your documents.
  • Your local queries — local-mode search runs entirely on your machine. Nothing leaves.
  • Raw public corpus text — miners exchange verified vectors, not source documents, in peer sync.

What DOES cross the network

  • Public corpus text — pulled from public sources by miner nodes (same data anyone can download)
  • Vector deltas — int8 embeddings + scale metadata, content-hashed
  • Verification proofs — job manifests and similarity attestations
  • Hosted tier (opt-in) — premium queries are processed on our infrastructure; local mode stays local, always

Security Model

"Will this software hijack my computer?" — Fair question. Here's the answer, current state included.

🟢 True today

  • No root / admin required — the pipeline runs as a normal user process
  • Hard resource caps — memory and CPU limits enforced at the process level (systemd MemoryMax)
  • Open pipeline — parse, embed, quantization and merge logic are inspectable scripts, not black boxes
  • Governance disclosure — signed epochs can pause or throttle the network; this power is documented, not hidden (see Governance)

⚪ Shipping with client v1

  • Sandboxed worker — containerized execution, filesystem isolation
  • Signed binaries — every release cryptographically signed; unsigned clients refuse to run
  • Signed job manifests — tasks are only accepted from the founding authority key
  • Reproducible builds — release artifacts verifiable from source
  • Automatic updates — signed, rollback-capable

Governance — Stated Plainly

We won't pretend this is fully decentralized when it isn't. Here's the honest split:

Peer-to-peer layer

  • Miner nodes discover each other directly (libp2p DHT)
  • Work results propagate peer-to-peer
  • No single server hosts the index

Founding authority layer

  • Task manifests are signed by the founding key — unsigned work is rejected by design
  • The authority can schedule epochs, throttle workloads, and pause network operations
  • Epoch validity is capped at 24h — no signed renewal means the network halts by design, not by accident
  • This power is exercised under the Brain Constitution v1.0 — 12 articles, versioned, changeable only by explicit founder decision

We call this model Sovereign Network: P2P at the data layer, constitutional monarchy at the governance layer. If that's not for you, the open pipeline means you can fork the brain.
